# Migration skill

Every Alembic migration follows the §6.2 default conventions. Deviations require an in-file comment explaining why.

## The conventions

### UUIDs

- Primary keys are UUIDs generated by Postgres `gen_random_uuid()`.
- Server default, not Python-side default — keeps inserts atomic and lets Postgres do the work.

```python
sa.Column(
    "id",
    postgresql.UUID(as_uuid=True),
    primary_key=True,
    server_default=sa.text("gen_random_uuid()"),
)
```

UUIDv7 ecosystem support in SQLAlchemy 2.0 is uneven as of v3.4 of the scope. Revisit Phase 4.

### Monetary values

- Stored in **local currency**. Reporting currency computed on read using FX rates.
- Column type: `numeric(18, 4)`.
- **Never `float`.** Floating-point error in financial reporting compounds. Stripe enforces this; we do too.

```python
sa.Column("planned_spend_local", sa.Numeric(18, 4), nullable=False)
```

### Percentages and ratios

- Column type: `numeric(8, 4)`. Allows up to 9999.9999%, sufficient for drift percentages and confidence scores.

```python
sa.Column("spend_drift_pct", sa.Numeric(8, 4), nullable=True)
```

### FX rates

- Column type: `numeric(20, 10)`. Some currency pairs need many decimal places.

```python
sa.Column("fx_rate_used", sa.Numeric(20, 10), nullable=False)
```

### Timestamps

- Column type: `timestamp with time zone` (`timestamptz` in shorthand). **Always.**
- Stored UTC, converted at the edges.
- **Never `timestamp without time zone`.** Naive timestamps in a multi-market product cause bugs that are expensive to diagnose.

```python
sa.Column("created_at", sa.DateTime(timezone=True), server_default=sa.func.now(), nullable=False)
sa.Column("updated_at", sa.DateTime(timezone=True), server_default=sa.func.now(), onupdate=sa.func.now(), nullable=False)
sa.Column("deleted_at", sa.DateTime(timezone=True), nullable=True)
```

### JSONB

- Column type: `jsonb`, never `json`. JSONB indexes and queries; JSON is opaque.
- GIN index for filtered fields.

```python
sa.Column("dimensions", postgresql.JSONB, nullable=False, server_default="{}")
op.create_index("client_taxonomy_dimensions_gin", "client_taxonomy", ["dimensions"], postgresql_using="gin")
```

### Soft delete

- Column: `deleted_at timestamptz` nullable.
- Partial index on hot query paths: `WHERE deleted_at IS NULL`.

```python
op.create_index(
    "actuals_active_idx",
    "actuals",
    ["client_id", "market_id", "date"],
    postgresql_where=sa.text("deleted_at IS NULL"),
)
```

### Indexes

- Every FK gets an index.
- Every `(client_id, ...)` query pattern gets a composite index. Multi-tenancy means almost every query starts with `client_id`.
- GIN index on JSONB columns that are filtered.

### Constraint names

- Pattern: `{table}_{column}_{type}`.
- Predictable matters more than concise. Migration debugging gets fast when names are guessable.

Examples:
- `actuals_unique_pull` (the §7.14 idempotency constraint)
- `plan_lines_plan_id_fk`
- `connector_auth_organization_platform_unique`

```python
op.create_unique_constraint(
    "actuals_unique_pull",
    "actuals",
    ["client_id", "market_id", "channel", "campaign_external_id", "date", "source"],
)
```

## Entity-specific rules

### Actuals

UNIQUE constraint on `(client_id, market_id, channel, campaign_external_id, date, source)` — the §7.14 idempotency key. Every connector pull is an upsert on this constraint.

### AuditLog

Append-only. No update path. Indexes:
- `(organization_id, occurred_at)` for tenant-scoped time queries
- `(entity_type, entity_id)` for entity history

### EncryptedSecret

Index on `key_version` for rotation queries.

### ConnectorAuth

UNIQUE constraint on `(organization_id, platform)`. One auth per org per platform — that's the §7.14 credential model.

### RecommendationLog

Indexes for calibration queries: `(client_id, recommendation_source, recommended_at)`.

## Phase 1a special: provisioning Phase 2/4 tables empty

Per §7.21, all Phase 2/4 tables are provisioned (empty) in Phase 1a to avoid retrofit:
- `MacroSignal` (Phase 2 populated)
- `ContributionFit` (Phase 2)
- `IncrementalityResult` (Phase 2/3)
- `ForecastRun` (Phase 3)

When provisioning these in Phase 1a, use the same conventions above. They get populated later; the schema is final now.

## Workflow

1. Identify scope section authorizing this change.
2. `cd apps/api && alembic revision --autogenerate -m "<short_snake_case>"` (or manual revision for backfills).
3. Review autogenerated migration against the conventions above.
4. Fix violations — autogenerate sometimes uses `json` instead of `jsonb`, defaults to `timestamp without time zone` on `DateTime` columns without `timezone=True`, omits indexes on FKs.
5. Test up + down + up locally to confirm reversibility.
6. Run affected tests.
7. Document any deviation from defaults with a comment in the migration file.
8. Commit with reference to scope section in the message.

## Deviation policy

You may deviate from these defaults, but document why in a comment in the migration file. The defaults exist because each is load-bearing:

- Monetary precision affects Phase 2 modeling inputs.
- JSONB GIN indexes affect taxonomy filter performance in Phase 1c.
- Soft delete partial indexes affect every query in steady state.
- Predictable constraint names make migration debugging fast.
- Timezone-aware timestamps prevent multi-market correctness bugs.

If you're tempted to deviate "for performance" or "because the autogenerate output was different," resist. Match the convention.
