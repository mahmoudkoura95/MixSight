# Frontend conventions (apps/web)

Next.js 14+ App Router, TypeScript strict mode, Tailwind, shadcn/ui per §6.1. Other library choices (charting, virtualization, etc.) are open — pick on first use, document, stick with it.

**Default to less.** The same principle from root `CLAUDE.md` applies here. Don't introduce performance work, abstraction layers, or component libraries that the scope and current measurements don't justify.

## Conventions

- **Server components by default.** Add `"use client"` only when needed (state, effects, browser APIs, event handlers on interactive surfaces).
- **No `any` in TypeScript.** Strict mode is non-negotiable per §6.1. If a type seems impossible to express, refine the API contract.
- **API types come from `packages/types/`** — generated from the OpenAPI spec. Regenerate on backend schema change. Never hand-write API types.
- **TanStack Query for all server state.** Don't use `useEffect` + `fetch`. Don't put server state in `useState`.
- **shadcn/ui first.** If a shadcn component fits, use it. Add a new dependency only when shadcn doesn't have an equivalent.
- **Tailwind for styling.** No CSS modules, no styled-components.
- **One charting library across the codebase.** Decide on first chart; stick with it.

## Surface-specific contracts

### Pacing surfaces (§7.2.2, §7.16)

- Weekly snapshot view and current week view are **distinct routes**, not view toggles. Different data freshness, different affordances, different LLM behavior.
- Every chart in the current week view renders the trailing 3 days with the "still settling" treatment per §7.16: lighter saturation + dotted top edge + tooltip. This is a shared component, not re-implemented per chart.
- Every pacing surface shows a freshness stamp at the top: "Data current as of {timestamp} {timezone}. Daily refresh re-fetched last {N} days."
- Filter bar above pacing table is **driven by `ClientTaxonomy`**, not hardcoded dimensions. New taxonomy dimensions appear in the filter bar without code change.

### Defense kit (§7.13)

- HTML server-rendered, PDF via Playwright (in API). Frontend renders an interactive preview that visually matches the PDF output.
- Narrative paragraph and outlook are rich-text editable; pacing table and reallocation block are structural (read-only structure, individual cells can be commented on).
- **Never block on LLM.** If `narrative_status` is `templated_fallback` or `failed`, show the templated text and a "Regenerate narrative" button. The defense kit is still complete and usable.

### Empty states (§7.18)

- Every list-rendering surface declares its empty state explicitly. No silent "no data" blanks.
- Use the `<EmptyState>` component from `packages/shared/`. Variants: `backfill_in_progress`, `partial_week`, `insufficient_data`, `no_active_plan`, `pre_flight`, `post_flight`, `no_filter_match`, `no_spend_in_market`, `no_conversion_baseline`.
- See `.claude/skills/empty-state/` before building a new surface.

### LLM-generated content

- Anything generated by LLM (drift explanations, defense kit narrative, parser previews) has a visible `narrative_status` indicator: ✓ generated, ⏳ pending, ↻ regenerating, ⚠ templated fallback, ✗ failed.
- "Regenerate" affordance always visible for failed/fallback states.

## Auth and tenancy on the client

- Clerk's `<SignedIn>`, `<SignedOut>`, `<RoleProtected>` for UI gating. Never assume server-enforcement is enough — but never trust client-side checks alone either.
- The current client/market context lives in URL state (`/clients/[clientId]/markets/[marketId]/...`), not React Context. URL is the source of truth so deep links work.
- `account_manager` role: hide admin surfaces entirely. `admin` role: full access.
- The connector reauth UI is **admin-only** (§7.19). AMs see "flag reauth needed" affordance instead.

## White-label (§6.4)

- Layer 1 (Growth+): logo + colors + PDF branding. Read from `Organization.branding_config` on every render.
- Layer 2 (Agency): custom domain via middleware on `app/middleware.ts`; branded email-from handled in API.
- Layer 3 (Enterprise): Phase 4 only.
- "Powered by MixSight" footer toggle: Agency tier and above.

## Performance discipline

**No optimization until measured.** Pacing table rendering might be fine without virtualization for a long time. Don't add `react-virtual` or memoization preemptively. When something feels slow in real use, profile it, then add the smallest fix that resolves it.

The exceptions — surfaces that are known to be heavy and earn upfront care:
- Defense kit PDF generation is heavy; lazy-load the preview on click (not on snapshot view mount).

That's the entire list. Everything else: ship simple, measure, fix when measured.
